# BF16 output head and optional layer synchronization — 2026-11-13

## Original bottleneck

The output head maps hidden size 5120 to vocabulary 248320. Its weights are
BF16 (2,542,796,800 bytes); the original `head_bf16_k` assigned one thread to
each vocabulary row, accumulating its dot product in FP64. The new optional
`head_bf16_warp_cuda` computes each row cooperatively across one warp and
accumulates in FP32. A group of four warps processes four rows per CTA.

### Isolated CUDA kernel (GPU1 RTX 5060 Ti SM120)

Measured by CUDA events, 5 rounds × 5 launches, excluding transfers and
weight upload, synthetic BF16 weights and FP32 activations:

| Shape | Original scalar FP64 | Warp FP32 | Kernel speedup |
|---|---:|---:|---:|
| H=5120, vocab=248320, T=1 | 21.45815 ms | 5.95337 ms | 3.604× |

Across **all 248320 logits**, the maximum absolute difference was
`1.90734863e-6` (RMS `4.09946883e-7`), and the greedy top token was identical
in this synthetic test. Six shapes passed correctness validation. These data
do **not** constitute proof of full model parity across arbitrary inputs.
Benchmark source: `kernels/tests/bench_head_bf16.cu` (standalone build).

### End-to-end with actual checkpoint

Two RTX 5060 Ti (PP2), CUDA 12.8, same model
`Qwen3.8-27B-Uncensored-NVFP4-MTP.gguf`, prompt token IDs
`6205,161421,303,220,17,1374,9911,1147,27053,6059,13` (11 tokens).
The output comprises 12 greedily generated tokens, requiring 11 new
`decode_step` calls after the seed. Timings exclude weight upload. One A/B run
per configuration, no statistically rigorous latency distribution yet.

| GEMV | BF16 head | Layer sync | Decode (11 steps) | Step/s |
|---|---|---|---:|---:|
| Scalar | FP64 scalar | On | 7086.443 ms | 1.55226 |
| Warp4 | FP64 scalar | On | 1815.483 ms | 6.05899 |
| Warp4 | FP32 warp | On | 1646.209 ms | **6.68202** |
| Warp4 | FP32 warp | Opt-out | 1641.528 ms | **6.70107** |

Every configuration emitted **identical 12-token IDs**:

`[271,248068,198,760,1156,16561,728,310,10033,22525,303,220]`.

With all three optimizations enabled, the 4-prompt
`scripts/check_generate.py` real-model smoke test passed:
greedy, prefill/decode logits agreement (within test tolerance), per-prompt
state isolation, and EOS handling.

The BF16 head improves throughput on this prompt by about **10.3% beyond
Warp4 GEMV**. Omitting two layer syncs improves this single-request result
by less than **0.3%**. Do not infer any multiuser overlap improvement from
these single-request results.

### Throughput for multiple states (real GGUF, combined opt-ins)

The rebuilt `test_pp2_batch g2` exercised independent decode states with
four decode steps per sequence, using all three optimizations:

| Number of requests | Sequential aggregate | Parallel aggregate |
|---|---:|---:|
| 1 | 6.702 tok/s | — |
| 2 | 6.699 tok/s | 7.015 tok/s |
| 4 | 6.693 tok/s | **7.027 tok/s** |

At N=4, parallel scheduling is **about 5% faster than sequential** but total
throughput does not grow proportionally to the number of clients. This is
interleaved independent decode, not a fused/batched GPU matrix computation.
Observed used VRAM at N=4 was 10180/11797 MiB (GPU0/GPU1), falling after
state cleanup. The corrected 11-case CPU admission gate also passed in the
GPU-linked build. This is a single short benchmark, not a stress test.

Flags (all are **off by default**):

```bash
export HERMES_NVFP4_GEMV=warp4
export HERMES_HEAD_BF16=warp4
export HERMES_DECODE_SKIP_LAYER_SYNC=1
```

The head and skip-layer-sync remain opt-in until real-model numerical
regression is broadened and concurrent requests have been checked. The
standalone head test uses synthetic weights; real-model validation so far
checks exact greedy token IDs and prefill/decode consistency, **not** full
vocabulary logit error between both heads on arbitrary prompts.
