## Build contract and reproducibility

All six new files reside under `kernels/` and are isolated from
`hermes_pp2`, `hermes_kernels` and `serving` by default.
The newly added CMake option
`HERMES_BUILD_Q8_1_EXPERIMENT=ON` is OFF by default and provides:

- `q8_1_gpu_bench`: separate CUDA executable; manually run only when
  both GPUs are exclusively reserved.
- `q8_1_real_capture_cpu`: CPU full original-GGUF/reference comparison.
- `q8_1_quant_cpu`: 3007 deterministic/random Q8 block cases plus
  1000 synthetic GGUF integer-dot checks, CTest host-only.

Fresh isolated same-source CMake scratch:
`/tmp/h27-q8-integrated-9u3lb9/build`.

- CUDA 12.8 SM120a CMake configure and both targets compile: PASS.
- `ctest -R q8_1_quant_cpu --output-on-failure`: 1/1 PASS.
- Real capture CPU checker: 10240 QKV outputs, RMSE
  `1.57648647082e-7`, maxabs `3.81469726562e-6`, PASS.
- Its CPU checker accepts a caller-supplied checkpoint hash as a
  declared identifier; it does **not** independently rehash the full
  19.7 GB file. Full GGUF SHA256 was separately verified by the
  authenticated layer0 diagnostic. Do not confuse this local checker
  with the independent manifest validator.

Commands from the project root:

## Release decision

Q8_1 quantization explains the **first** independent llama.cpp layer0
QKV discrepancy when the exact same activation vector and weights are
used. No full-model Q8 path is deployed or even wired into PP2.
The independent full-vocab comparison across 12 traces remains FAIL
and requires a matched model-wide investigation. The Q8 prototype
uses per-output-token GEMV with repeated raw weight reads and has
prohibitive performance for the requested priority:
**multiuser aggregate throughput > prefill > decode speed**.

No default changes, no CUDA manager lease installation, no Tabby
interruption and no production cutover are authorized by this experiment.
