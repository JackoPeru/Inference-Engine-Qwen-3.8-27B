## Release decision

Q8_1 quantization explains the **first** independent llama.cpp layer0
QKV discrepancy when the exact same activation vector and weights are
used. No full-model Q8 path is deployed or even wired into PP2.
The independent full-vocab comparison across 12 traces remains FAIL
and requires a matched model-wide investigation. The Q8 prototype
uses per-output-token GEMV with repeated raw weight reads and has
prohibitive performance for the requested priority:
**multiuser aggregate throughput > prefill > decode speed**.

No default changes, no CUDA manager lease installation, no Tabby
interruption and no production cutover are authorized by this experiment.

## Follow-up: explicit DP4A batched Q8_1 versus original Q8_1 (real GPU)

The standalone kernel was extended with the **strictly opt-in**
`--dp4a-ab` flag, preserving the original Q8_1 path in the same binary.
It reuses each 64-weight GGUF block over 8 input token rows, performs
signed integer dot products with native CUDA DP4A, and keeps the same
FP32-to-Q8_1 per-32 activation quantization. This test ran on the same
RTX 5060 Ti (GPU index 1), original GGUF and authentic llama layer0
capture. Ten CUDA-event iterations per configuration; no live services,
PP2, production kernels or inference model route were changed.

At T=64 the improvement over the original Q8 projection was **8.63×
in the same-process benchmark**, with 0 unbounded allocations and no
new persistent GGUF weight copy. The projected T64 Q8 scratch buffer
remains 368640 bytes. The benchmark observed a GPU allocation delta
of 41943040 bytes (includes CUDA context and allocations).

The previously measured raw Warp4 QKV projection took 9.056 ms for T64
under a *different* experimental run. Relative to 6.722 ms this is a
potential ~1.35× improvement, **not** a controlled matched A/B and
not a full-model or multiuser throughput measurement.

The T64 batch input rows 1..63 are deterministic perturbations, NOT
new genuine llama token positions; only row 0 has independent llama
QKV evidence. No speculation that this local comparison closes the
existing 12/12 independent full-vocabulary logit failures is warranted.
The DP4A path is still not linked into PP2 production runtime and is
disabled unless explicitly requested in the isolated benchmark.
The default inference path and release decision remain **NO-GO**.
