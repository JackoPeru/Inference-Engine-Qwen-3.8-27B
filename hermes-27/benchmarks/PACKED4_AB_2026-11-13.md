# PackedU32x4 — raw GGUF NVFP4 GEMV end-to-end A/B (13 November 2026)

**Status:** optional, real model checked for short greedy prompts, not yet
default or ready to replace a production server. No weight layout conversion.

The new `HERMES_NVFP4_GEMV=packed4` option replaces the GEMV kernel with a
vectorized per-row warp variant reading four GGUF blocks per warp iteration.
It still uses the **same 36-byte/64-weight GGUF**, BF16 activations and FP32
accumulation. `warp4` and original scalar remain available, scalar default.

## Full-model decode A/B

Actual `/home/matteo/hermes-27/models/Qwen3.8-27B-Uncensored-NVFP4-MTP.gguf`
on two RTX 5060 Ti 16 GiB GPUs, PP2, CUDA 12.8, independent sequence state,
11 seed IDs `6205,161421,303,220,17,1374,9911,1147,27053,6059,13`,
12 greedy generated tokens (11 actual decode steps beyond seed), no MTP.
Weights uploaded before the timed interval.

| Configuration | Decode step/s | Decode total (11 steps) |
|---|---:|---:|
| Scalar GEMV, scalar BF16 head, layer sync | 1.552 | 7086 ms |
| Warp4 GEMV + warp BF16 head + skip layer sync | 6.701 | 1642 ms |
| **Packed4 GEMV + warp BF16 head + skip layer sync** | **11.058** | **995 ms** |

Packed4 gives a **1.65x improvement over the preceding optimized path**
on this prompt, or about 7.12x over original scalar full-model decode.
All 12 token IDs were identical:
`271,248068,198,760,1156,16561,728,310,10033,22525,303,220`.
The 4-prompt `scripts/check_generate.py` gate passed with Packed4 active:
same greedy IDs, full prefill vs incremental logits tolerance, EOS and
separate prompt states.

`test_pp2_batch g1` with Packed4 also passed N2 distinct prompts, all four
steps, **max_abs 0** comparing batch-vs-single logits, plus parallel-step
sanity. `test_pp2_batch g2` passed N1/N2/N4 and the 11-case admission gate.

| G2 workload with Packed4 + BF16 + async | Aggregate tokens/sec |
|---|---:|
| N4 sequential (16 tokens) | 11.044 |
| N4 parallel (16 tokens) | **12.031** |

N4 parallel is only about 9% faster than sequential; no fused GPU batching
exists yet. N4 peak used memory 10180/11797 MiB (GPU0/GPU1), post-free
memory returned to the observed baseline. This is a short test, not a long
context stress run or statistically representative TPS percentile.

## Isolated CUDA kernel measurements

Worker-5's `kernels/tests/bench_warp_variants.cu` verified complete F-row
outputs on 7 shapes, 286 independent CPU FP64 sampled rows for each large
shape, and full greedy argmax. Absolute error vs scalar/Warp4 up to 3.82e-6.
Median CUDA-event measurements 5x20 launches, GPU0 RTX 5060 Ti:

| H x F | Existing Warp4 | Packed4 | Warp4/Packed4 |
|---|---:|---:|---:|
| 5120x10240 | 0.132045 ms | 0.090173 ms | 1.464x |
| 17408x5120 | 0.399131 ms | 0.162728 ms | 2.453x |
| 5120x17408 | 0.375350 ms | 0.154027 ms | 2.437x |

Full details in `kernels/tests/WARP_VARIANTS_REPORT.md`. Unlike CUTLASS W4A4
batched prefill, this optimization adds no A4 activation quantization and
does not need a second resident copy of the weights.

## Replication

```bash
export HERMES_NVFP4_GEMV=packed4
export HERMES_HEAD_BF16=warp4
export HERMES_DECODE_SKIP_LAYER_SYNC=1
python3 scripts/check_generate.py build/hermes_generate \
  /home/matteo/hermes-27/models/Qwen3.8-27B-Uncensored-NVFP4-MTP.gguf
build/test_pp2_batch g1
build/test_pp2_batch g2
```

For baseline change `HERMES_NVFP4_GEMV` to `warp4` or unset all flags. The
opt-in path is only supported when the weight pointer is 4-byte aligned and
H is a positive multiple of 64. The dispatcher retains fallback to Warp4
for incompatible shapes; launch failures fail closed. No default changes.
